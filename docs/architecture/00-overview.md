# 00 · 总览与架构

> 模块文档 · HitMind 架构文档集（索引见 [README](README.md)）。

**范围**：项目定位、架构分层、进程拓扑、能力范围、行为闭环、智能归属

## 1. 定位

本地优先、轻量、可被多个 Agent 共同读写的长期记忆服务。不同 Agent 是同一套记忆的**不同客户端**，共享同一个 Core 与同一个 SQLite 文件，而非各自独立的记忆库。

- 从日常工作中识别值得长期保留的信息 → 整理成可复用记忆 → 按需准确召回 → 维护新旧关系 → 控制规模。
- 存储收敛 **SQLite**（单文件、WAL 多进程可读、零运维），排除常驻重型服务与知识图谱。
- 向量化**可选**：依赖外部 OpenAI 兼容 embedding 服务；缺失或不可达时自动降级为 BM25-only，不因它不可用而挂（零云依赖，非零外部服务）。

## 2. 架构分层

```
        ┌───────────── 记忆 Core（宿主无关，单一真源） ─────────────┐
        │ schema · 存储(SQLite) · 检索 · 关系/版本 · 生命周期        │
        │ · 事务/并发 · scope · provenance                          │
        └───────────────────────────────────────────────────────────┘
           ▲                                         ▲
   ┌───────┴────────┐                    ┌───────────┴─────────────┐
   │ 有钩子的宿主      │                    │ 无钩子的宿主（走 MCP）     │
   │ 原生 Provider     │                    │ 其他 Agent                │
   │ (Provider + 钩子) │                    │ (MCP: stdio / HTTP)       │
   └────────────────┘                    └─────────────────────────┘
```

**硬原则：**

- **共享靠 Core + Schema + 同一个 DB**，不靠某个接口类。
- **Core 词汇必须 Agent 中立**（`agent_id / scope / tags` 这类）；`session`、`turn` 等宿主概念一律挡在绑定层。
- 接口层是**平级兄弟**，各自贴合宿主扩展机制，不必长得一样：有钩子的宿主可做每轮自动召回；MCP 只是工具集。

## 3. 进程拓扑

- Core 是**嵌入式 Python 库**；能 import Python 的宿主在进程内直连同一 SQLite 文件（零 IPC、最快）。
- **嵌不了 Python 的宿主**走**薄 MCP server**：`stdio` 本地 / `streamable-HTTP` 带 bearer。
- 两者共用**同一个 SQLite 文件** → 并发纪律是核心问题，见 [01 · 数据模型 §6](01-core-data-model.md)。

## 4. 能力范围

**Core + Hermes 绑定 + MCP server**。

- Core：11 个动词门面，零宿主依赖。
- Hermes 绑定：Provider + 压缩钩子 + 闲时后台线程 + 桌面配置页。
- MCP：当前实现 **stdio 传输**（11 个工具，与 Hermes 插件一致：9 核心 + export/import），`agent_id` 来自 `--agent-id` / `HITMIND_AGENT_ID`；streamable-HTTP + bearer（token 名 = agent_id 做 per-agent provenance）为规划项。

## 5. 行为闭环

| 阶段 | 契约 |
|---|---|
| 写入 | 显著性判定 + 规范化成"记忆单元" |
| 关系 | 版本与关系判定（去重 / 合并 / 隔离 / 替代） |
| 读取 | 召回 + 可度量"准确" + 延迟预算 |
| 生命周期 | 衰减 / TTL / 合并 / 归档 / 容量上限（**不删只归档**） |
| 贯穿 | 多 Agent 共读写：身份 / 作用域 / 并发 / 协议，是前四阶段前提 |

## 6. 智能归属

判断分两件事，成本/时机天差地别，必须分开：

| | 关系判定（重复/冲突/替代） | 抽象整理（提炼/合并/定稿 topic） |
|---|---|---|
| 时机 | 前台、同步、写时即决 | 后台、可延迟、可关 |
| 智能 | **确定性**（Dice / 否定 / 规则），零 LLM | **可选 LLM**（离线批处理） |
| 兜底 | 拿不准 → `inactive` 复核队列 | 关掉后纯确定性仍成立 |

**结论**：确定性关系判定（前台）+ 复核队列必做；LLM 整理做成**可插拔后台模块**——轻量零模型是默认态，聪明是增量。写路径**永不调用 LLM**。
