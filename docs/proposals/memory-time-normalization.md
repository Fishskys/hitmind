# 提案：写入时时间 / 实体归一化

> **提案文档**（非现状）。本文件描述**拟议**设计，实施前不代表代码现状；架构现状以 [`docs/architecture/`](../architecture/README.md) 为准。相关决策此文档独立记录，不写回架构现状文档。
>
> 依据：SeCom (arXiv 2502.05589)、MemGAS (2505.19449)、EMem (2511.17208)、LycheeMemory V2 (2608.12990) 的研读结论——**记忆单元应短、自包含、带归一化时间/实体**。

**范围**：时间/实体归一化（写入时）、时间结构化索引、配置、验证。

> 备注：**父-子块（语义切块）方案已从本提案删除**。经评估，长记忆改为在**抽取阶段**由 LLM 按语义单元拆分、单条上限 1024 字符、每条尽量自包含（见抽取提示词），不在检索侧另建父子块索引。

---

## 0. 动机

- 现状最弱题型：**相对日期 9.1% / 时间题 16.7%**，根因是相对时间未在写入时按逻辑时间归一。
- 多篇文献（EMem / Lychee 等）均在写入时把"昨天/下周三"等按会话时间归一为绝对日期、并规范化实体，显著利于后续时间类问答。

## 1. 目标 / 非目标

**目标**
- 提升时间类问题（相对日期、时间约定、时间题）的召回与作答准确率。
- **零新第三方依赖**（SQLite + 标准库）；**热路径零 LLM**（归一为确定性/轻量）。
- 原文不丢：归一结果与原文并存，可整体关闭。

**非目标（明确不做）**
- 父子块 / 语义切块索引（已删）。
- 知识图谱 / GMM / PPR。
- 查询时 LLM 规划或过滤。
- 用 LLM 做写入时的实体消解 / 指代绑定（放闲时任务，不进热路径）。

## 2. 关键设计决策（已定）

| 编号 | 决策 | 取值 |
|---|---|---|
| D1 | 归一化时机 | 写入时（`capture()`/`remember()` 存库前），以条目 `created_at`（逻辑时间）为基准 |
| D2 | 原文处理 | **不改原文**；归一结果写 `normalized_text`（新增列或存 metadata），原文照存 |
| D3 | 相对→绝对替换 | 只做**能确定映射**的词（日/周/月/季/年/数量偏移）；**模糊词不猜**，打 `temporal_approximate` 标记 |
| D4 | 实体归一 | 仅确定性轻量处理；代词不自动绑定；跨条实体消解若需 LLM → 闲时任务 |
| D5 | 时间索引 | 从归一结果抽 `event_date` 建结构化索引（SQLite，零 LLM） |

## 3. 时间 / 实体归一化（确定性为主）

**挂载**：`capture()`/`remember()` 存库前，以条目 `created_at`（逻辑时间）为基准，生成 `normalized_text`（**原文不动**）。

**相对→绝对日期（确定性替换，只改"能确定映射"的）**

| 类别 | 词表 | 规则 |
|---|---|---|
| 日偏移 | 前天/昨天/今天/明天/后天/大后天 | `created_at` ±1/0/+1/+2/+3 天 |
| 周偏移 | 上周X/这周X/本周X/下周X/周X/星期X | 定位该周第 X 天（周一为周始） |
| 周段 | 上周/这周/下周 | 上周一~周日 / 本周 / 下周一~周日 |
| 月段 | 上个月/这个月/下个月 | 月初/月末区间 |
| 季/年 | 去年/今年/明年；上/本/下季度 | 对应年/季区间 |
| 数量偏移 | N天/周/月/小时 前/后 | 解析 N 后按单位加减 |
| 模糊 | 最近/前几天/过几天/这几天 | **不强行归一**，打 `temporal_approximate` 标记 |

- 输出形如 `"下周三"` → `"下周三（2026-11-18）"`（保留原词 + 括号补绝对日期），利于 BM25 与作答。
- 代词（他/她/它）**不自动绑定**（易错）；跨记忆实体消解若需 LLM → **放闲时任务**，不进热路径。

## 4. 时间结构化索引（P1，零 LLM；下一阶段）

> **状态：本阶段未实现**。本次先交付 §3 的写入时归一化（已验证有效）；事件日期抽取与 `date_range` 过滤作为下一步单独实现，避免留下未使用的配置项。

- 从归一结果抽 `event_date` 写入一列或附属表 → recall 支持 `filters.date_range` 过滤与按日期近邻排序。
- 纯 SQLite 索引，无外部依赖。

## 5. 配置项（进 `config_schema`，桌面可调）

| 分组 | 键 | 默认 | 说明 |
|---|---|---|---|
| 抽取 | `time_normalize` | true | 相对日期归一开关（写入时按逻辑时间补绝对日期；原文保留，另存 `normalized_text` 仅用于检索索引、不注入作答） |

> `time_index` 随 §4 一并延后，届时再进配置面。

## 6. 成本 / 风险

- **风险：时间归一误改** → 只做确定映射 + 保留原词；模糊词不猜；可整体关闭。
- **风险：归一文本与原文不一致** → 二者并存，原文是唯一真源。
- 成本：纯字符串处理，无额外模型调用、无显著存储增长。

## 8. 落地顺序建议

1. **时间归一化**（改动最小、直击最弱项）。
2. P1：时间结构化索引。

> 实施遵循仓库纪律：先出改动清单与测试计划、经批准后动手；core 保持零第三方依赖；热路径零 LLM。

### 8.1 实施状态（已落地：写入时归一化）

- **模块**：`hitmind/core/timenorm.py`（纯 stdlib）。确定性词表→补绝对日期；保留原词；模糊词不动；异常回退原文。
- **存储**：`memories.normalized_text`（`_add_column` 幂等加列，兼容存量库、不重建）。`content` 原文永不改写。
- **写入**：`capture()/remember()/update()` 以逻辑时间 `created_at` 为基准生成 `normalized_text`。
- **检索**：向量与 FTS 索引文本改用 `normalized_text`（`6月5日` 与 `上周五` 均可命中）；`embed_documents` 仍只嵌正文、`title` 走元数据（与基线一致，保证 A/B 干净）。**`normalized_text` 仅作内部检索索引，不随召回结果返回、不进入作答上下文**——避免把绝对日期喂给作答模型导致「编造日期」。
- **规则要点**：带前缀（上周X/这周X/下周X/上周/下周…）按精确周/月/季/年区间；**裸"周X/星期X"取最近的那一天**（如周六说"周一"= 即将到来的周一，避免算成已过去的错误日期）。
- **配置**：`time_normalize`（默认 true，记忆抽取分组；env `HITMIND_TIME_NORMALIZE`）；关闭则 `normalized_text` 为 NULL。
- **测试**：`tests/test_timenorm.py`（偏移/区间/最近周X/保留原词/模糊词/存库/召回/关闭）。

## 9. 参考论文与启发

（保留文献依据；"粒度"相关工作已落地为**抽取阶段的 LLM 语义拆分 + 自包含提示词**，不再走检索侧父子块。）

- **SeCom**（arXiv 2502.05589）：主题段粒度最优；自然语言冗余是检索噪声。→ 借鉴"冗余=噪声"（抽取时精炼）；不引入 LLMLingua、不在检索侧分段。
- **MemGAS**（arXiv 2505.19549）：多粒度 + GMM 关联图 + 熵路由 + PPR。→ 仅借鉴"粒度重要"思想；图/PPR/查询时 LLM 不采纳（与轻量冲突）。
- **EMem**（arXiv 2511.17208）：事件级自包含单元（EDU）+ 召回偏置过滤。→ 借鉴"短/自包含单元"（落到**抽取拆分 + 自包含提示词**）、"写入时归一实体/时间"（本提案 §3）。
- **LycheeMemory V2**（arXiv 2608.12990）：语义分段 + 段级编码 + 写入时相对日期/指代归一 + 结构化证据索引。→ 借鉴"写入时时间归一"（§3）、"结构化时间索引零 LLM"（§4）；其段级批处理精神已由现有 chat 批次 / episode 对齐。

**一句话对应**：时间/实体归一（§3）← EMem / Lychee 写入时归一；时间索引（§4）← Lychee 结构化证据索引；"短、自包含"← EMem EDU / SeCom 段级 —— 通过**抽取阶段 LLM 按语义单元拆分 + ≤1024 字符 + 自包含提示词**实现，而非检索侧父子块。
